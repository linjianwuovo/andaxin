# 净室章程（Clean-room charter）

这份文件是这个仓的最高约束。任何一次改动，包括我自己做的，都得先过这一页。

## 一条底线

本仓不继承轻小信（Relianttt/lightxin）以及它的任何派生仓（含 `linjianwuovo/linxiaoxin`，即本机 `../lightxin-main`）的一行源码。不是"改一改"，不是"参考着写"，是从空文件开始敲。

具体禁止：

- 从旧仓复制粘贴任何 `.kt`、`.xml`、`.gradle.kts` 文件或其片段，哪怕只是 import 段。
- 把旧仓的函数体、`when` 分支顺序、Composable 的参数顺序当模板照着改。
- 沿用旧仓的标识符命名体系（`Lx*` 前缀、`Routes`、`BASE_*` 常量名等）—— 结构重新起。
- 把旧仓的分包结构当默认答案。

允许（这些不是"代码"，是事实和外观）：

- 数值：颜色十六进制、圆角 dp、字号、接口域名、字段名、阈值、协议常量。
- 机制：某个流程该怎么走（比如"上传前把 WGS-84 转 BD-09"、"三秒一个点"）。
- 外观：旧版截图、他认可的界面样子。
- 抓包取证结论 —— 但必须是我们自己抓的，见下一条。

## 数值也要有出处

协议层的每一个接口名、字段、阈值，落进代码时旁边要写清证据来自哪次抓包或哪次反汇编。取不到证的一律不写，宁可留空、宁可那屏少显示一行。旧仓里"学长入库时写的样子、没有证据顶着"的那部分（考勤两个接口、二维码格式），在这里不算已知。

## 怎么查有没有破戒

写完一批，跑这条：把新仓每个 `.kt` 与前仓 `beta` 分支逐文件比对连续重复行，超过 6 行连续相同（去掉空行和纯括号行）就算污染，得重写。

```bash
# 连续 6 行以上相同即报告；只读比对，不改任何文件
python tools/check_clean_room.py ../lightxin-main beta
```

（`tools/check_clean_room.py` 在骨架编过之后补上，先记在这里当验收项。）
